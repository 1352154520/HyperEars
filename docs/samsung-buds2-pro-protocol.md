# Samsung Galaxy Buds2 Pro 协议记录

## 范围与证据

本适配以 Galaxy Buds2 Pro（SM-R510）为已验证基线，依据 GalaxyBudsClient 5.1.2 的公开
实现和状态测试样本整理。贡献者已在 Fix15 实机验证电量、三态降噪、触控菜单与长按设置；
Fix16 的连续写入优化以及 Buds2、Buds FE 和共享服务回退仍需分别实机复核。

## 传输与帧

- RFCOMM 服务 UUID：`2e73a4ad-332d-41fc-90e2-16bef06523f2`
- 帧：`FD [size:2LE] [message id] [payload] [crc16:2LE] DD`
- `size` 包含 message id、payload 和 CRC；最低为 3。
- CRC 为 CRC16-XMODEM（多项式 `0x1021`、初值 `0`），覆盖 message id 与 payload。
- 解码器按连续字节流工作，处理拆包、粘包、前导噪声、非法长度和错误 CRC；只有完整且校验
  通过的状态帧可以成为 Adapter 的能力证据。

|---:|---|---|
| `60` | 耳机 → 模块 | 基础状态与组件电量 |
| `61` | 耳机 → 模块 | 扩展状态、电量、降噪与设置 |
| `42` | 耳机 → 模块 | 写入确认；携带原命令 ID 与设备确认参数 |
| `77` | 耳机 → 模块 | 降噪状态更新 |
| `78` | 模块 → 耳机 | 降噪 / 关闭 / 环境声 |
| `79` | 模块 → 耳机 | 左右长按噪声组合，分别为 ANC / 环境声 / 关闭三个布尔字节 |
| `6F` | 模块 → 耳机 | 单耳降噪控制 |
| `7A` | 模块 → 耳机 | 语音检测 |
| `84` | 模块 → 耳机 | 环境声等级 |
| `86` | 模块 → 耳机 | 均衡器开关与预设 |
| `88` | 模块 → 耳机 | 管理器客户端信息 |
| `8B` | 模块 → 耳机 | 侧音 |
| `90` | 模块 → 耳机 | 触控锁与各手势保留状态 |
| `92` | 模块 → 耳机 | 左右耳长按动作（语音助手 / 噪声控制 / 音量 / Spotify） |
| `95` | 模块 → 耳机 | 耳缘双击 |
| `96` | 模块 → 耳机 | 超高环境声 |
| `AF` | 模块 → 耳机 | 无缝连接（线值为反向布尔） |

扩展状态确认前，适配器仅保留 Android 标准电量与流转能力。合法状态出现后才开放对应能力；
协议断开或控制权让给 Galaxy Wearable 时清除私有状态和专属卡片。写入后以耳机的通用 ACK
或后续完整状态回报为准，不在模块侧伪造成功状态。`0x90` 的 ACK 首参数回显“触控启用”线值：
`00` 表示触控已锁定、`01` 表示触控已解锁，映射到 `touchpadLocked` 时必须取反。
耳缘双击音量由独立的 `0x95` 控制，不受 `0x90` 主触摸锁自动约束；卡片总开关关闭时需一并
关闭 `0x95`，重新开启时恢复锁定前的耳缘双击值。
二级触控菜单中的单击、双击、三击、长按和通话手势通过 `0x90` 的完整七字节设置写入，
左右耳长按动作使用 `0x92` 两字节写入。三级“长按”页按左右耳设置动作；四级“噪声切换
组合”页支持 ANC ↔ 环境声、ANC ↔ 关闭、环境声 ↔ 关闭，按“确定”后发送 `0x79`。
组合编码左侧三个布尔字节后接右侧三个；扩展状态 `payload[21]` 高半字节是左侧，低半
字节是右侧，位 2/1/0 分别代表 ANC/环境声/关闭。未知组合不假设为默认组合。

Fix15 沿用参考客户端 `TouchpadPageViewModel` 的动作切换流程：发送 `0x92`，若任一侧
为噪声控制且两侧组合已知，则跟随 `0x79`；`0x88` 仅为管理器信息，不是保存或查询命令。
长按动作/组合写入后展示待确认值，匹配 ACK 或扩展状态解除“同步中”；对迟到旧值的保护
限于当前会话和 90 秒内的状态事件，不常驻轮询、不跨重连保存目标、不自动覆盖官方 App。

用户提供的 Fix13 16:32 日志中，16:29:37 发送左语音/右噪声（`01 02`），16:29:39 扩展
状态确认 `12`；16:31:35 重连后的报告仍为 `12`。16:31:46 又发送 `02 02` 后报告变为
`22`，后续重连仍为 `22`。本段记录未证明设备保存失败；随后 Fix15 已由贡献者报告实测可用。

Fix16 将已确认状态与请求目标分开保存。快速连续修改 `0x90` 手势时，后一帧合并当前会话
尚待确认的位；`0x92`/`0x79` 超时仅清除请求目标并显示耳机上报值，只有对应 ACK 或匹配
扩展状态才确认成功。Buds2、Buds FE 依照公开实现选择各自状态修订；只命中共享 UUID 的
未知型号仅使用固定位置的电量和三态噪声字段，不开放型号专属设置。

## 实机复核清单

Fix16 需要在目标 HyperOS / MiLink 版本上重点核对：快速连续关闭多个触控手势时是否都保留；
长按动作和噪声组合的显示是否只在对应确认后结束同步；Galaxy Wearable 前后台切换时的运行时
退避与恢复。Buds2、Buds FE 和其他共享服务型号还需分别核对电量位置、三态降噪及设置边界。
